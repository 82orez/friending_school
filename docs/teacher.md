**강사 지원→승인 flow** (역할 부여): 직접전환 폐지. 학생이 `/teacher/apply`에서 지원 → `teacher_applications` 저장 → admin이 `/admin/teacher-requests`에서 승인(role=teacher)/거절. 액션 `submitTeacherApplication`(`src/app/teacher/apply-actions.ts`): 가드 (1)로그인 (2)role≠teacher/admin (3)필수값(first/last·nationality(화이트리스트)·gender(화이트리스트)·**center(필수: `"none"`=null 허용·빈값 차단·그 외 uuid 존재검증)**·bio≥10·experience·zoom_url·avatar) (4)`rateLimit(teacher-apply:IP)` (5)기존 '신청' 중복 차단 (6)본인 세션 client insert(`user_id`=getUser, RLS `_insert`=uid 일치) → best-effort `sendTeacherApplicationNotification` + `revalidatePath("/teacher/apply")` → **`redirect("/teacher/apply?submitted=1")`**(아래 제출 성공 토스트). 메일러는 `applications`용과 별개 함수(`src/lib/mailer.ts`). role 단일값이라 **friender도 강사 지원 차단**(page redirect + 액션 거부).

**⚠️ 지원서 제출 성공 토스트는 폼이 아니라 페이지에서 띄운다**(강사·프렌더 공통): 제출이 성공하면 재검증된 페이지가 `status==='신청'` 분기로 바뀌며 **폼 컴포넌트가 언마운트**돼, `useActionState` 상태 업데이트와 RSC 재렌더가 같은 transition에서 함께 커밋되면서 폼 내부 `useEffect([state])` 토스트가 **실행되지 않는다**(실제 겪음. `StudentProfileForm`·`TeacherProfileForm`은 언마운트가 없어 정상 동작 — 차이는 언마운트뿐). 해결: 액션이 `revalidatePath` 후 **`?submitted=1`로 `redirect`**(⚠️ `redirect()`는 `NEXT_REDIRECT`를 throw하므로 **알림 메일 try/catch 바깥**에서 호출) → page가 `searchParams`(Next 16이라 Promise) 읽어 **`<ToastOnMount queryKey="submitted" message=…>`**(`src/components/ToastOnMount.tsx`, client, 렌더 결과 없음 — ref 가드로 마운트 1회 `toast.success` 후 `router.replace`로 파라미터 제거해 새로고침 재발화 방지; `NoticeViewCounter` + `SuccessBanner` 패턴 조합) 렌더. 두 `*ApplyState` 타입에 **`success` 플래그 없음**(성공은 리다이렉트로만 전달), 폼의 `useEffect`는 **에러 토스트만** 담당.
